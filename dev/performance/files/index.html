    Reading and writing files¶

    MDAPY, OVITO and ASE read and write LAMMPS dumps, LAMMPS data files and extended XYZ of the same systems, plain and gzipped, from 4 000 to nearly 10 million atoms. A program is timed only where it reads the positions that MDAPY wrote, or writes a file that MDAPY reads back as the system.

    Results¶

    A node of the Triton cluster of Aalto University, alone for the run: two Intel Xeon Gold 6148 (40 cores, two NUMA nodes), 191 GB, Linux. Python 3.13, MDAPY 2.0.0 built with GCC 12.3, OVITO 3.17.1 and ASE 3.29.0 from pip. The analyses ran on another node, with Intel Xeon Gold 6230, so their times do not compare with these.

    How many times faster MDAPY is: a row for each case, the largest gain on top, and a point for each size, larger and darker for more atoms; the number on the right is the speed-up at the largest size.

    What they show¶

    • OVITO: from 32 000 atoms on, MDAPY reads the three formats 4.7 to 24 times faster and writes them 8.2 to 24 times faster. At 4 000 atoms MDAPY reads 1.0 to 1.3 times faster and writes 2.0 to 3.6 times faster.
    • ASE: from 32 000 atoms on, MDAPY reads 27 to 308 times faster and writes 43 to 130 times faster; at 4 000 atoms, 4.9 to 12 and 9.4 to 13 times. ASE reads a data file of nearly 10 million atoms in 45 s and 18 GB of memory.
    • Gzip: MDAPY compresses on all threads. From 256 000 atoms on it writes gzipped files 14 to 35 times faster than OVITO and 48 to 185 times faster than ASE. It reads them 1.1 to 2.0 times faster than OVITO and 3.8 to 14 times faster than ASE: most of that time is decompressing.
    • Nearly 10 million atoms take MDAPY 0.12 to 0.15 s to read in each format, and 0.26 to 0.35 s to write with every digit; gzipped, 3.2 to 3.7 s to read and 1.8 to 2.0 s to write.

    Times and memory¶

    Every case at every size: the shortest of three times, and the memory each call took beyond the system, the peak resident memory of the process minus its peak before the timings.

    Cases¶

    Case MDAPY OVITO ASE
    Read a LAMMPS dump mdapy.io.read(path) import_file(path).compute() ase.io.read(path, format="lammps-dump-text")
    Write a LAMMPS dump mdapy.io.write(path, system) export_file(data, path, "lammps/dump", columns=[...], precision=17) ASE writes no dumps
    Read a LAMMPS data file mdapy.io.read(path) import_file(path, atom_style="atomic").compute() ase.io.read(path, format="lammps-data", atom_style="atomic", units="metal")
    Write a LAMMPS data file mdapy.io.write(path, system) export_file(data, path, "lammps/data", atom_style="atomic", precision=17) ase.io.write(path, atoms, format="lammps-data", atom_style="atomic", masses=True)
    Read extended XYZ mdapy.io.read(path) import_file(path).compute() ase.io.read(path, format="extxyz")
    Write extended XYZ mdapy.io.write(path, system) export_file(data, path, "xyz", columns=[...], precision=17) ase.io.write(path, atoms, format="extxyz")

    The gzipped cases are the same calls with a path that ends in .gz.

    The system is fcc copper with its atoms displaced at random by 0.1 Å along each axis. The dump holds the columns id type x y z; the data file the atom style atomic, with the mass of copper; extended XYZ the species and the positions.

    MDAPY writes every number with as many digits as it takes to read it back exactly, at most 17. OVITO is asked for 17 significant digits. ASE writes the positions of a data file in full and those of extended XYZ with 8 decimals, so its extended XYZ is about a third smaller.

    How it is measured¶

    • Each program runs in a process of its own. MDAPY and OVITO have 40 threads (MDAPY_NUM_THREADS, OVITO_THREAD_COUNT); ASE reads and writes in Python on one.
    • Before the timings, a separate process checks each program. Reading: the positions it reads are those MDAPY reads within 1e-12 Å, and the types and elements are the same. Writing: MDAPY reads back the file the program wrote, and finds the positions within 1e-12 Å (1e-8 Å for the extended XYZ of ASE) and the same types and elements. A program that differs is not timed.
    • The file to read is written by MDAPY before the timings, so it is in the file cache of the operating system: the times are those of reading and parsing, not of the disk. Writing goes to the local disk of the node as the operating system takes it.
    • The times of MDAPY for LAMMPS data files were measured last, on another node of the same kind.
    • Each process first reads or writes a system of 500 atoms, so that loading libraries and starting threads are not timed, then three times the system; the shortest time counts.
    • Making the system, and converting it into OVITO's data collection or ASE's atoms for writing, are not timed.

    Running it¶

    The comparison is benchmarks/comparison.py in the source repository, the group files of its cases. It needs OVITO (pip install ovito) and ASE (pip install ase).

    python benchmarks/comparison.py run --group files \
    --sizes 4000 32000 256000 2048000 9841500 \
    --threads 40 --memory 170 --timeout 1800 --output files.json   # as above
python benchmarks/comparison.py table files.json
python benchmarks/comparison.py plot files.json files.png
